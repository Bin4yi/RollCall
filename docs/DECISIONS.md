# Decisions

| Date | Decision | Why | Alternatives |
|---|---|---|---|
| 2026-11-06 | **Sidecar language: Node/TypeScript** with `@smartspectra/node-sdk@3.4.0` | Officially supported on Windows and loads on the dev machine; same language as the game and shared schema | C++ SDK (Windows is experimental, needs CMake/MSVC); Electron renderer SDK (forces Electron for everything) |
| 2026-11-06 | Default input is browser-captured frames pushed with `sendFrame()`; `HUSH_INPUT=camera` is the alternative | Windows docs say built-in webcams don't work natively, and that's the only camera here | Native `useCamera` only (needs buying a USB webcam) |
| 2026-11-06 | SDK runs in a supervised child; parent owns the vitals socket, child owns the frame socket | A native crash can't kill the game, and the game's connection survives a restart. Frames skip the parent to avoid IPC overhead | All in one process (one crash ends the session) |
| 2026-11-06 | No MediaPipe | The SDK provides 478 landmarks; head motion comes from their bounding box | MediaPipe on the same frames (extra CPU competing with the 25 fps floor) |
| 2026-11-06 | **Breath rate and regularity come from `upperTrace` peak intervals, not `breathing.rate`** | The SDK rate is a 30 s average, longer than an encounter, so it can't be the "fast lever" in §7 | SDK rate as specified (players' breathing changes wouldn't register in time) |
| 2026-11-06 | SDK starts at the tutorial, so calibration ends about 30 s later without feeling longer | Breathing confidence is 0 for the first 30 s | 20–30 s calibration as briefed (impossible for breathing) |
| 2026-11-06 | `apps/sidecar/runtime` is a separate npm project outside the workspace | SDK install is 386 MB across all platforms, which would break "fresh clone running in < 5 min" and slow CI | Workspace dependency; pnpm overrides dropping platforms |
| 2026-11-06 | SDK telemetry off, `requestInsight()` never called | Simplest accurate privacy story for the consent screen | SDK defaults |
| 2026-11-06 | No "cleared measurement" claim; 18+ is HUSH's own label | SDK docs state metrics have not been FDA cleared, which contradicts §14 of the brief | Following the brief's wording (would be false) |
| 2026-11-06 | Golden tests and Judge Mode use clearly labelled synthetic sessions (`data/sessions/synthetic/`) until real recordings exist; real files take priority automatically | Recordings need a person at a webcam and an API key; game work mustn't block on that | Wait for recordings; pass synthetic data off as real (dishonest) |
| 2026-11-06 | HRV is recorded but doesn't affect play | 60 s window is longer than an encounter, and it's easily misread as a health signal | Add to noise model |
| 2026-11-06 | `assets/` stays out of git; `tools/pack_assets.py` writes picked variants as WebP to `apps/game/public/hush-assets` (485 MB to 7 MB) | A fresh clone must run Judge Mode, and it also loads far faster | Commit everything; Git LFS |
| 2026-11-06 | Lull's animation is code, not sprite sheets; the Listener uses the walk sheet only | Lull's glow must follow live noise, and the 48-frame sheets risk GPU texture limits on integrated graphics | Play all generated sheets |
| 2026-11-06 | The noise dial is drawn in code rather than using `ui_noise_meter` | That art has a needle painted in, which would show two needles | Regenerate the art |
| 2026-11-06 | Listener voice uses Web Speech only; Piper and ElevenLabs are not implemented | ElevenLabs would expose a key in the browser unless proxied, Piper needs a separate binary, and Web Speech works with no setup | Route TTS through the sidecar (worth revisiting if the voice sounds weak in playtests) |
| 2026-11-06 | Replaces the row above: ElevenLabs dropped. Listener voice is pre-rendered with OpenAI `gpt-4o-mini-tts` by `pnpm voice:gen`, with Web Speech as the runtime fallback. Meta isn't used for voice | Meta's Model API is [speech-to-text only](https://dev.meta.ai/docs/). Pre-rendering keeps the key out of the browser, adds no delay, gives Judge Mode the voice, and means pulse numbers are never sent anywhere. [OpenAI's guide](https://developers.openai.com/api/docs/guides/text-to-speech) requires disclosing AI voices (shown on the title screen) and lists this model as shutting down on Jan 6, 2027, which doesn't affect clips already rendered | Live TTS through the sidecar (sends pulse readings to OpenAI, adds latency, needs a key to play) |
| 2026-11-06 | Director visits track the player; noise-triggered visits can be dodged by moving | Keeps encounters on the planned pacing, while rewarding quick thinking after a noise | Always dodgeable (encounters too rare); never dodgeable |
| 2026-11-06 | No Electron shell (`apps/desktop` not created) | Browser capture works in Chrome and Edge, so Electron isn't needed for camera access | Electron with the SDK's renderer path |
| 2026-11-06 | **Pivot from HUSH to Roll Call.** Game code removed in one commit; the last HUSH state is `b0a5d63`. Kept: the SDK worker, `VitalsFrame` schema, recorder, replay and sim sources, browser frame capture, CI | The game hid its value behind an 8–12 minute run. A still, seated spot check against a personal baseline is how the SDK is meant to be used | Keep HUSH; a 90-second HUSH; TELL; Aftertaste |
| 2026-11-06 | Capture at 30 fps, not the 15 fps in the brief | Presage docs: "don't let the camera fall below roughly 25 fps" | 15 fps as briefed (documented to fail validation) |
| 2026-11-06 | Raw NV12 at 1280x720 on the same computer; JPEG at 640x480 elsewhere; canvas fallback for Safari | Raw is proven live here but too heavy for Wi-Fi; Safari lacks `MediaStreamTrackProcessor`. JPEG quality impact is unverified | WebRTC (far more moving parts); raw everywhere |
| 2026-11-06 | Vitals worker runs locally on Windows; server SDK build is opt-in | The only proven path, and Presage's terms page could not be read to confirm server use is allowed | Linux VM from the start; Electron |
| 2026-11-06 | Web stack: React, Vite, Tailwind, Motion, Recharts | As briefed; code split so athletes never download the charts | Next.js (no need for server rendering) |
| 2026-11-06 | libSQL with Drizzle, hand-written additive migrations | Prebuilt binaries avoid native compiles on Windows, and no migration tool is needed at runtime | better-sqlite3 (native build); drizzle-kit migrations |
| 2026-11-06 | Real and demo data separated by a `workspace` column | One-click Judge Mode on any deployment without risking real data | A second database |
| 2026-11-06 | Judge Mode can never start the SDK, call an LLM or notify anyone | Public visitors must not spend the owner's credit | Rate limiting |
| 2026-11-06 | Check-in logic runs on the server, for live, replay and sim alike | The same code path is what gets tested and demoed | Client-side replay |
| 2026-11-06 | Art budget $2: sprite sheets plus code-drawn suns, skies and logo mark; no style-bible anchor | Owner's hard cap during the build. Spent $0.62, so there is room for more | Separate images at $40 as briefed |
| 2026-11-06 | No generated video | OpenAI shut down the Sora Videos API on Sep 24, 2026 | Another video provider |
| 2026-11-06 | Calendar day comes from the server (`APP_TIMEZONE`) | An evening settle check must not land on tomorrow's UTC date. Coach and athletes in very different time zones would see day boundaries at the coach's midnight | Per-athlete time zones |
| 2026-11-06 | Status and date use the rolling assessment, with status held by a 0.25 margin | The brief asks for hysteresis without a number | No margin (flickers) |
| 2026-11-06 | Board sorts by status, then how far from usual | Most-off first within a status | Alphabetical; nudge first |
| 2026-11-06 | No StrictMode | Its double-run effects would start the SDK twice per check-in | Guarding against double starts |
| 2026-11-06 | Coach-edited messages are not filtered for banned words | They are the coach's own words; only drafts and the app's own text are checked | Blocking the coach |
